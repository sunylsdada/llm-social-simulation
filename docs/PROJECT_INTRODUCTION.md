# 项目详细介绍

## 一、这个项目是什么

这是一个用大语言模型驱动的社会舆情仿真框架。它把一次公共事件抽象成“事件包”，用 LLM 扮演网民、政府和分析师，按天模拟信息流、评论互动、情绪变化和政府应对，最后把仿真曲线与评论侧的情绪曲线做形态对比。

它适合用来做：

- 公共事件舆情演化的探索性研究；
- 不同政府沟通策略的沙盘比较；
- 信息时效性、群体情绪、信任变化等机制实验；
- 多事件、多平台的仿真流程搭建。

它不适合直接用来：

- 预测某次真实事件的舆情走向；
- 替代真实民意调查；
- 在没有校准的情况下宣称“某个策略最优”；
- 直接拿仿真绝对值当作现实效应量。

## 二、核心思想

传统舆情仿真常常把网民简化为同质群体，或者只用一个情绪标量。本项目把网民拆成三个可观测、可更新的心理状态：

- **恐慌 `panic`**：对事件和自身处境的恐惧程度；
- **政府信任 `government_trust`**：对负责处置的官方机构的信任程度；
- **谣言易感性 `rumor_susceptibility`**：对未经证实信息的轻信与转发倾向。

每个网民 agent 有稳定的画像（年龄、性别、大五人格、活跃度），也有每天变化的心理状态。它每天看一份个人信息流，选择一个行动，然后根据“最新消息”和“自己做了什么”更新状态。

政府不是直接命令网民，而是通过改变信息环境来影响舆情：

- 沉默观望；
- 删除负面评论；
- 发布坦诚通告；
- 注入无关话题、降低旧帖曝光；
- 组合使用上述手段。

## 三、系统角色

| 角色 | 数量 | 职责 |
|---|---:|---|
| 网民 agent | 可配置（示例 4 个） | 浏览信息、行动、反思、更新三项状态 |
| 舆情分析师 agent | 1 | 把当天帖子和评论整理成简报 |
| 政府 agent | 1 | 根据简报分配目标权重，从五种策略中选一个 |
| 信息环境 | 1 | 管理帖子池、评论、热度、置顶、删帖、降权 |

网民 agent 看不到“政府选择了哪个策略标签”，只能通过信息流里多了什么、少了什么来感知政府动作。这样可以避免策略标签直接进入 agent prompt，减少“照着标签演戏”的问题。

## 四、15 天式的事件结构

事件包用“天”作为基本单位，通常包含：

- 一个自然日起止窗口；
- 若干阶段（例如事发、扩散、对峙、回落）；
- 每天至少一条事实刺激；
- 可选的历史官方表态；
- 一个决策日列表（政府只在转折点决策）。

示例事件是 3 天的小样本，用于演示；真实事件可以配置成 15 天、30 天或更长。框架不强制 15 天，天数、阶段、决策日都由 `event.json` 决定。

## 五、网民 agent 的构成

### 5.1 静态画像

- `name`：作者名或化名；
- `age` / `gender`：按事件配置的先验采样，或由使用者提供；
- `big_five`：作者级大五人格标签；
- `activity`：High / Middle / Low，决定每天上线概率。

### 5.2 动态状态

- `panic`；
- `government_trust`；
- `rumor_susceptibility`。

初始值可以由 LLM 根据画像生成，也可以在没有初值时使用大五启发式 fallback。

### 5.3 每日三步

1. **是否上线**：按活跃度概率抽取；
2. **看信息流**：最多 5 条帖子，每条最多 10 条一级评论和 3 条回复；
3. **行动与反思**：评论、回复、赞踩、转发或沉默；然后更新三项状态。

反思 prompt 要求 agent 先判断信息时效性，再给分数，并记录它依据的最新/过时帖子 id。

## 六、政府决策的五步

1. 分析师汇总当天舆情；
2. 政府 LLM 给“防恐慌 / 遏谣言 / 建信任”分配权重；
3. 按权重查效用矩阵；
4. 选加权效用最高的策略；
5. 写入政府记忆，下一次决策时回看上次预测是否准确。

效用矩阵默认全为 0。标定前政府会默认选 S1，这是占位，不是研究结论。正式比较前需要按事件做反事实实验，把测出的相对效果写回 `processed/utility_matrix.json`。

## 七、外部环境与信息流

帖子池只增不减。旧帖子不会自动消失，但会随着时间变成背景，靠热度和随机抽样竞争展示名额。

信息流分为四组：

- 今日最新消息：当天发布或更新的、关于事件本身的事实进展或官方表态；
- 今日其他内容：当天发布但不是事件进展的内容；
- 近期信息：未超过时效阈值，可作背景；
- 已过时信息：超过时效阈值，只作背景，不再作为状态变化依据。

这套机制的目的是避免同一件旧事被反复当成新冲击，导致恐慌曲线只涨不落。

## 八、验证思路

真实侧通常只能稳定提取一个指标：负面情绪指数，定义为焦虑和愤怒的平均值。政府信任、恐慌、谣言易感性这些潜变量很难从一句评论里可靠读出。

因此验证只做两件事：

1. 把真实负面情绪曲线与仿真恐慌曲线分别归一化，比较形状；
2. 检查 agent 说的话是否像它的人设，而不是只比较绝对水平。

仿真侧用 `panic` 作为负向情绪代理；`trust` / `rumor` 只作为内部状态报告，不做外部验证。

## 九、数据要求

一个事件至少需要：

- `raw_comments.csv`：评论 id、作者、正文、发布时间；
- `stimuli.csv`：每天至少一条事实刺激；
- `event.json`：事件窗口、阶段、列名映射、Prompt 背景。

可选：

- 作者级大五缓存；
- 初始心理状态缓存；
- 每个事件的效用矩阵；
- 平台/语言/人口学先验。

## 十、运行流程

```text
准备事件包
  → 导入评论
  → 清洗
  → LLM 打分
  → 作者级大五
  → 生成 user.csv
  → 生成初始状态
  → 准备刺激源
  → 校验
  → 仿真
  → 日度曲线
  → 形态对比
  → 图表
```

免费步骤与付费步骤分开：导入、清洗、画像构建、刺激源、校验不调用 LLM；逐条打分、作者级大五、初始状态生成会调用 LLM，需要显式加 `--yes-paid`。

## 十一、架构设计

详见 `docs/ARCHITECTURE.md`。核心分层是：

```text
事件层 → 画像层 → 仿真层 → 记录与验证层
```

每一层只通过事件目录里的规范文件交互，不直接共享内存状态。这样多事件可以顺序运行，缓存和输出不会串。

## 十二、当前版本的边界

- 事件数据由使用者提供，仓库不附带抓取数据集；
- 示例是合成数据，只用于冒烟；
- 效用矩阵默认未标定；
- LLM 采样有随机性，正式实验需要多种子；
- 真实侧只有一条负面情绪曲线，不能做多指标外部验证；
- 策略效果是仿真模型内的相对效果，不是现实世界的效应量。
